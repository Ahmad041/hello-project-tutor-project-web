Standalone atau terintegrasi?

Standalone berarti alur utama berdiri sendiri dengan data lokal. Terintegrasi berarti ada pertukaran data dengan layanan lain, misalnya payment gateway atau inventori pusat. Standalone tidak selalu berarti tidak pernah memakai internet.

Latihan KasirKita berdiri sendiri: satu proses aktif, penyimpanan TXT lokal, pembayaran tunai, dan tidak ada integrasi pihak luar.

Penjelasan Konsep: Empat Kotak di Meja Kasir

Bayangkan kamu punya empat buah kotak di mejamu: tiga "Kotak Master (Kategori, Barang, Pelanggan)" dan satu "Kotak Transaksi (Penjualan / Nota Belanja)".

1. Kotak-Kotak Master (Entitas Master)

Fungsi: Kotak ini berisi tumpukan kartu katalog paten: Kode Kategori, Kode Barang, Nama Barang, Harga Satuan, dan Profil Pelanggan.

Sifat Data: Kotak master ini datanya jarang berubah. Kamu hanya memasukkan kartu baru ketika ada produk baru dari distributor, atau mengganti kartu jika harga resmi naik. Kartu di kotak ini adalah sumber kebenaran utama (single source of truth).

Bisa Masuk Antar-Master: Barang dari kotak master bisa dimasukkan ke dalam kotak master juga! Contohnya, kartu Kategori Alat Tulis (K01) dimasukkan ke dalam Kotak Barang untuk melabeli Buku Tulis A5 (P001). Hubungan master-ke-master ini sah dan sering digunakan dalam database.

Penerapan di C: Kotak ini disimpan di file master seperti data/kategori.txt dan data/produk.txt dengan struct seperti CategoryMaster dan ProductMaster.

2. Kotak Transaksi (Entitas Transaksi)

Fungsi: Kotak ini adalah tempat penampungan nota atau struk belanja dari pelanggan setiap kali terjadi penjualan.

Sifat Data: Kotak ini isi datanya PASTI BERUBAH-UBAH dan bertambah terus. Setiap kali ada yang beli, kasir menulis nota baru lalu menjatuhkannya ke dalam kotak ini sepanjang hari (bertambah terus / append-only). Nomor nota melonjak, barang belanja berganti, dan nominal pembayaran berubah.

Cara Kerja Relasi: Di lembar nota pesanan, kamu tidak perlu menulis nama barang atau harganya secara panjang lebar berulang kali. Cukup menulis "Kode Barang: P001, Jumlah Beli: 2". Ketika harus menghitung total bayar, kasir memegang nota tersebut lalu mencari kartu "P001" di Kotak Barang untuk melihat harganya.

Penerapan di C: File transaksi.dat (atau data/penjualan.txt). Isinya adalah tumpukan data struct SaleTransaction yang disimpan dengan mode append (fopen("transaksi.dat", "ab") atau "a"), lalu menggunakan looping untuk mencocokkan kode barang di transaksi dengan master agar bisa mencetak total harga.

Inti Pemahaman Analogi:
Perbedaan utama bukan semata larangan fisik, melainkan dinamika stabilitas data. Data Master disiapkan sebagai fondasi acuan yang jarang berubah (bahkan sesama master bisa saling terhubung seperti Kategori ke Barang), sedangkan Data Transaksi isinya selalu bergerak, berubah, dan bertambah seiring kasir melayani transaksi.

Pola Kode C: Struktur Data & Looping Pencocokan

Pola C · Master vs Transaksi
// 1. DATA MASTER: Disimpan di data/ (Jarang Berubah)
typedef struct {
    char id_category[21];  // K01 (Primary Key Kategori)
    char name[64];         // Alat Tulis
} CategoryMaster;

typedef struct {
    char id_product[21];   // P001 (Primary Key Produk)
    char id_category[21];  // K01 (Foreign Key merujuk Master Kategori: Master ke Master!)
    char name[128];        // Buku Tulis A5
    int price;             // 12000
    int stock;             // 20
} ProductMaster;

typedef struct {
    char id_customer[21];  // C001 (Primary Key Pelanggan)
    char name[128];        // Rani
    char phone[32];        // 0812345678
} CustomerMaster;

// 2. DATA TRANSAKSI: Disimpan di data/penjualan.txt (Mode Append "a" - Pasti Berubah-Ubah)
typedef struct {
    char id_sale[21];      // N001 (Nomor Struk - berubah setiap transaksi)
    char id_customer[21];  // C001 (Foreign Key merujuk Pelanggan)
    char id_product[21];   // P001 (Foreign Key merujuk Produk Master)
    int quantity;          // Berubah sesuai belanjaan pembeli
    int unit_price;        // Harga snapshot saat transaksi
    char timestamp[25];    // Waktu transaksi yang selalu berubah
} SaleTransaction;

// Program C mencocokkan kode barang transaksi dengan data di master:
int hitungSubtotal(SaleTransaction trx, ProductMaster katalog[], int jumlahProduk) {
    for (int i = 0; i < jumlahProduk; i++) {
        if (strcmp(trx.id_product, katalog[i].id_product) == 0) {
            return trx.quantity * katalog[i].price; // Cocokkan harga dari master!
        }
    }
    return 0; // Tidak ditemukan di katalog master
}

Skenario yang Digunakan Sepanjang Tutorial

Temukan atribut dari kebutuhan

Mulai dari kebutuhan pengguna, bukan menambah kolom tanpa tujuan. Periksa contoh dokumen dan formulir toko untuk menemukan data apa yang harus masuk, disimpan, dan keluar. Atribut dikelompokkan dalam tabel entitas mandiri. Pada tahap identifikasi awal ini, kita hanya mendata atribut alami masing-masing entitas tanpa Foreign Key (relasi antar-entitas akan dibentuk nanti saat perancangan relasi dan normalisasi).

Sederhana di C: Gunakan int untuk bilangan bulat (harga, stok, jumlah, bayar) dan array karakter char[N] untuk teks dengan satu slot ekstra terminator NUL \0. Semua ID memakai char[21] untuk menampung teks hingga 20 karakter. Validasi string juga menolak delimiter | dan newline bila disimpan pada format TXT.
