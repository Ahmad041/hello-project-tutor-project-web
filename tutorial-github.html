01

Mengapa Proyek Kelompok Wajib Memakai Git?

Penyebab kegagalan nomor satu tugas besar pemrograman bukanlah logika C yang rumit, melainkan bencana file tertimpa saat tenggat waktu pengumpulan tinggal menghitung jam.

Perbedaan Utama Git & GitHub:
• Git: Perangkat lunak mesin waktu di laptop masing-masing untuk mencatat riwayat perubahan file kode.
• GitHub: Website cloud untuk menyimpan salinan repositori Git bersama, sehingga seluruh anggota tim bisa bertukar kode secara otomatis dan teratur.

Dengan GitHub, setiap anggota kelompok memiliki bukti otentik kontribusi nyata pada commit graph. Dosen atau asisten praktikum dapat memeriksa dengan transparan siapa yang aktif menulis kode dan siapa yang tidak.

Prinsip Kerja Kelompok: Jangan pernah mengirim file kode mentah via grup chat! Satu file main.c yang kamu kirim di WhatsApp bisa menimpa 50 baris fungsi yang baru saja diselesaikan temanmu semalaman.

Analogi Pabrik Paket: Kode yang kamu ketik ada di Meja Kerja. Perintah git add memasukkannya ke Kardus, git commit menyegel kardus di Gudang, dan git push mengirimnya via Truk Kargo ke Cloud.
02

4 Wilayah Kerja Git yang Wajib Kamu Pahami

File tidak langsung loncat ke internet saat kamu menekan tombol simpan (*Ctrl + S*). Git menggunakan 4 pos pemeriksaan untuk memastikan hanya kode yang siap yang dikirim ke tim:

terminal — kasirkita-c 
# 1. Cek file mana saja yang sedang berubah di meja kerjamu
git status

# 2. Masukkan file yang sudah selesai dites ke kardus (Staging)
git add src/main.c src/lib.h

# 3. Segel kardus dengan pesan riwayat yang jelas (Commit)
git commit -m "[FEAT] Pasang border CRT ganda pada lib.h"

# 4. Kirim seluruh kardus tersegel ke repositori GitHub tim (Push)
git push origin main
Rumus Format Pesan Commit Standar:
Gunakan awalan yang konsisten agar rekan tim langsung paham saat membaca riwayat GitHub:
• [FEAT] : Menambah fitur baru (misal: menu kasir, hitung diskon).
• [FIX] : Memperbaiki bug (misal: cursor offset gotoxy, looping tak henti).
• [DOCS] : Memperbarui catatan atau komentar kode.

03

Feature Branching: Bekerja Paralel Tanpa Tabrakan

Di kelompok berisi 3–4 orang, bayangkan jika semua orang mengedit cabang main bersamaan. Konflik pasti meledak. Solusinya: buat branch per fitur modul.

terminal — branch workflow 
# 1. Buat dan langsung pindah ke branch baru milikmu
git checkout -b feat/modul-3-ui-console

# 2. Koding dengan tenang di IntelliJ IDEA, lakukan add & commit
git add src/lib.c
git commit -m "[FEAT] Tambah modul border gotoxy"

# 3. Push branch milikmu ke GitHub (bukan ke main!)
git push origin feat/modul-3-ui-console
Rekomendasi Pembagian Branch KasirKita:
• feat/modul-1-flowchart : Anggota 1 (Alur probis & validasi data).
• feat/modul-2-relasi : Anggota 2 (Struktur struct master-transaksi).
• feat/modul-3-ui-crt : Anggota 3 (Antarmuka console lib.h & gotoxy).
• feat/modul-4-file-uat : Anggota 4 (Baca/tulis file .txt & UAT).
Analogi 04: Siklus Harian Daily Routine
Analogi Mengambil Buku Catatan: Sebelum kamu mulai menulis di pagi hari, selalu ambil (git pull) catatan terbaru yang disetor temanmu kemarin. Jangan menulis di atas kertas usang!
04

Rutinitas Harian: Aturan Emas Push & Pull

Kunci sukses kerja tim tanpa konflik adalah disiplin sinkronisasi. Ada dua kebiasaan sederhana yang jika diterapkan, akan menghilangkan 95% potensi masalah:

terminal — daily sync 
# ATURAN 1: Saat baru buka laptop / sebelum mulai koding
git checkout main
git pull origin main

# ATURAN 2: Gabungkan perubahan terbaru main ke branch fiturmu
git checkout feat/modul-3-ui-console
git merge main

# Sekarang kamu aman koding di atas kode paling mutakhir!
Kapan Harus Push? Push-lah setiap kali sebuah fungsi kecil selesai dan berhasil di-compile (misal: "selesai buat menu utama", "selesai validasi input harga"). Jangan menunggu proyek selesai 100% baru di-push di akhir minggu!
Analogi 05: Menulis di Kertas Sama Conflict Markers
Analogi Dua Tulisan: Dua orang mencoret baris nomor 15 di kertas yang sama. Git tidak tahu mana yang benar, sehingga Git bertanya: "Pilih tulisanmu, tulisan temanmu, atau gabungan keduanya?"
05

Menangani Merge Conflict dengan Kepala Dingin

*Merge conflict* bukanlah error fatal, melainkan fitur proteksi Git agar pekerjaan temanmu tidak tertimpa tanpa izin. Saat konflik terjadi, Git akan memberi tanda penunjuk:

c-code — resolve conflict 
# 1. Buka file yang konflik di IntelliJ IDEA
# 2. Hapus baris penanda: <<<<<<<, =======, dan >>>>>>>
# 3. Sisakan hanya kode yang benar:

printf("== KASIR KITA MINIMARKET v1.0 ==\n");

# 4. Simpan file, lalu commit penyelesaian konflik:
git add src/main.c
git commit -m "[FIX] Selesaikan konflik judul menu utama"
git push origin feat/...
Fitur Ajaib IntelliJ IDEA: Saat terjadi konflik di IntelliJ, akan muncul tombol "Resolve Conflicts". Klik tombol itu! IntelliJ akan menampilkan jendela perbandingan 3-kolom yang sangat mudah: kamu cukup mengklik tanda panah untuk memilih versi mana yang dipakai.
Analogi 06: Satpam Penyaring Sampah Security Filter
Analogi Satpam Penjaga: File .gitignore adalah satpam yang melarang file binary besar (.exe, .o) dan konfigurasi laptop pribadi (.idea/) masuk ke repositori bersama.
06

Template .gitignore Wajib C di IntelliJ IDEA

Buat file bernama persis .gitignore di folder utama (root) proyek kalian. Salin dan tempel daftar berikut agar repositori tetap bersih dan cepat:

.gitignore — root repo 
# === IntelliJ IDEA / CLion Internal Cache ===
.idea/
*.iws
*.iml
cmake-build-*/

# === Binary C Executables & Objects ===
*.exe
*.o
*.obj
*.out
*.dll
*.so

# === File Temporary KasirKita ===
temp/
*.log
faktur_temp.txt

# === OS Metadata ===
Thumbs.db
.DS_Store
⌨️
Shortcut Cepat IntelliJ IDEA GUI:
• Tekan Ctrl + K : Membuka jendela visual Commit (pilih file dan ketik pesan).
• Tekan Ctrl + Shift + K : Melakukan Push ke GitHub.
• Tekan Ctrl + T : Melakukan Update Project (Pull) sebelum mulai koding.
