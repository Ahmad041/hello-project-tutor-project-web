PANDUAN VISUAL KASIRKITA · MODE 2D

Judul: Master & Transaksi

1. Kotak Master (Kategori, Barang, Pelanggan):
Fungsinya adalah menyimpan kartu acuan paten toko. Sifatnya datanya jarang berubah dan menjadi sumber kebenaran utama. Barang dari kotak master bisa dimasukkan ke dalam kotak master juga (relasi master ke master, seperti bola Kategori yang dimasukkan ke Kotak Barang untuk memberi label kategori).

2. Kotak Transaksi (Penjualan / Nota Kasir):
Fungsinya adalah menampung struk/nota belanja. Sifatnya isi datanya pasti berubah-ubah dan bertambah terus (append-only). Setiap detik kasir melayani pembeli, keranjang belanja berganti, jam transaksi bergerak, dan nominal belanja dihitung ulang dengan mencocokkan kode barang ke master.

⚡
Siap! Klik bola kategori untuk menghubungkan antar-master, atau klik bola produk untuk mulai transaksi.

Penjelasan Konsep: Empat Kotak di Meja Kasir

Bayangkan kamu sedang menjaga meja kasir toko Rani. Di mejamu terdapat dua kelompok kotak penyimpanan: Kotak-Kotak Master (Kategori, Barang, Pelanggan) dan Kotak Transaksi (Penjualan / Nota Belanja).

1. Kotak-Kotak Master (Entitas Master)

Fungsi: Kotak ini berisi tumpukan kartu katalog paten. Setiap kartu menyimpan informasi acuan tetap: Kode Kategori, Kode Barang, Nama Barang, Harga Satuan, dan Profil Pelanggan.

Sifat Data: Kotak master ini datanya jarang berubah. Kamu hanya memasukkan kartu baru ketika ada barang baru dari distributor, atau mengganti kartu jika ada kenaikan harga resmi. Kartu di kotak ini adalah sumber kebenaran utama (single source of truth).

Bisa Masuk Antar-Master: Barang dari kotak master bisa dimasukkan ke dalam kotak master juga! Contohnya, kartu Kategori Alat Tulis (K01) dimasukkan ke dalam Kotak Barang untuk mengelompokkan Buku Tulis A5 (P001). Hubungan master-ke-master ini sah dan sering diterapkan di database relasional.

Penerapan di Bahasa C: File master seperti data/kategori.txt dan data/produk.txt. Kartu-kartunya adalah struct seperti CategoryMaster dan ProductMaster yang dibaca saat program pertama kali dibuka.

2. Kotak Pemesanan / Penjualan (Entitas Transaksi)

Fungsi: Kotak ini adalah tempat penampungan lembaran nota atau struk belanja dari pelanggan setiap kali terjadi aktivitas transaksi.

Sifat Data: Kotak ini isi datanya PASTI BERUBAH-UBAH dan bertambah terus (high volatility & append-only). Setiap detik kasir melayani pembeli, isi kotak langsung berubah: nomor struk berganti, item belanjaan berbeda, jumlah kuantiti berbeda, jam transaksi berbeda, dan total bayar berubah.

Cara Kerja Relasi: Di lembar nota pesanan, kamu tidak perlu menulis ulang seluruh nama barang atau harga secara panjang lebar. Cukup mencatat kode referensi: id_product: P001, qty: 2. Ketika menghitung total bayar, kasir mencocokkan kode P001 ke Kotak Barang untuk mengambil harganya.

Penerapan di Bahasa C: File transaksi.dat atau data/penjualan.txt. Isinya tumpukan SaleTransaction yang disimpan dengan mode append (fopen("transaksi.dat", "ab") atau "a"), di mana baris baru terus bertambah tanpa henti.

Tabel Perbandingan Karakteristik: Master vs Transaksi

Aspek Pembeda Entitas Master (Kategori, Barang, Pelanggan) Entitas Transaksi (Penjualan & Nota Belanja)
Definisi Data acuan dasar yang dipakai berulang kali sebagai patokan. Catatan histori peristiwa/kejadian bisnis pada waktu tertentu.
Sifat Perubahan Isi Jarang Berubah (statis, hanya saat ada update resmi katalog). Pasti Berubah-Ubah (sangat dinamis, setiap pembeli datang).
Hubungan Antar-Kotak Bisa masuk ke sesama master (misal Kategori ➔ Barang). Meminjam referensi ID dari kotak master untuk nota.
Contoh di KasirKita CATEGORY, PRODUCT, CUSTOMER SALE (Header Nota), ITEM (Baris Belanja)
Siapa yang Mengubah Pemilik toko / admin katalog barang. Kasir saat melayani pembeli di meja checkout.
Peran Kunci (Key) Menyediakan Primary Key (PK) (misal id_category, id_product). Menyimpan Foreign Key (FK) yang merujuk ke PK Master.
Operasi File di C Dibaca berulang kali ("r" / "rb"); diperbarui jika stok diubah. Ditambah di akhir file secara terus menerus ("a" / "ab").
Konsekuensi File Kosong Aplikasi macet/tidak bisa jualan karena katalog barang belum ada. Aplikasi tetap normal, artinya belum ada penjualan hari ini.
Inti Pemahaman:
Perbedaan utama bukan semata larangan fisik, melainkan dinamika data: Data Master disiapkan di awal sebagai fondasi paten yang jarang berubah (bahkan sesama master bisa saling terhubung seperti Kategori ke Barang), sedangkan Data Transaksi isinya selalu bergerak, berubah, dan bertambah seiring transaksi kasir berlangsung.

Contoh Implementasi Representasi Data di Bahasa C

Struktur Data Master (Termasuk Relasi Antar-Master) vs Transaksi di C 
// 1. DATA MASTER: Disimpan di file teks/binary (Jarang Berubah)
typedef struct {
    char id_category[21];  // K01 (Primary Key Kategori)
    char name[64];         // Alat Tulis
} CategoryMaster;

typedef struct {
    char id_product[21];   // P001 (Primary Key Produk)
    char id_category[21];  // K01 (Foreign Key merujuk Master Kategori: Master ke Master!)
    char name[128];        // Buku Tulis A5
    int price;             // 12000
    int stock;             // 20
} ProductMaster;

typedef struct {
    char id_customer[21];  // C001 (Primary Key Pelanggan)
    char name[128];        // Rani
    char phone[32];        // 0812345678
} CustomerMaster;

// 2. DATA TRANSAKSI: Disimpan di data/penjualan.txt (Mode Append "a" - Pasti Berubah-Ubah)
typedef struct {
    char id_sale[21];      // N001 (Nomor Struk - berganti setiap transaksi)
    char id_customer[21];  // C001 (FK merujuk Master Pelanggan)
    char id_product[21];   // P001 (FK merujuk Master Produk)
    int quantity;          // Berubah sesuai belanjaan pembeli
    int unit_price;        // Harga snapshot saat transaksi terjadi
    char timestamp[25];    // Waktu transaksi yang selalu berubah
} SaleTransaction;

// Program C mencocokkan kode transaksi dengan master untuk menghitung total:
int hitungSubtotal(SaleTransaction trx, ProductMaster katalog[], int jumlahProduk) {
    for (int i = 0; i < jumlahProduk; i++) {
        if (strcmp(trx.id_product, katalog[i].id_product) == 0) {
            return trx.quantity * katalog[i].price; // Cocokkan harga acuan master!
        }
    }
    return 0; // Produk tidak ditemukan di master
}
