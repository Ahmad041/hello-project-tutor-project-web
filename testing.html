01Uji program C dan file TXT

Gunakan folder data sementara dan fixture yang disalin untuk setiap kasus. Pengujian tidak boleh mengubah data pengguna. Semua skenario berikut adalah rencana; belum merupakan hasil uji aplikasi yang dibangun pembaca.

Unit

Validasi input, hitungan uang, overflow, batas array, dan parser record.

Integrasi

Baca/tulis TXT, simpan gagal, backup, startup recovery, dan ekspor nota.

Aktifkan -Wall -Wextra -Wpedantic. Gunakan assert.h; bila compiler mendukung, jalankan build test dengan AddressSanitizer/UndefinedBehaviorSanitizer.

Cara menjalankan

  1. Buat fixture data awal dan salin ke folder test terpisah.
  2. Kompilasi test bersama modul input, storage, dan checkout; jangan sertakan main.c aplikasi.
  3. Jalankan test assert; kode keluar harus 0. Jangan menambahkan -DNDEBUG pada build test.
  4. Uji menu secara manual dan cocokkan file setelah restart.
  5. Catat hasil aktual, bukti, bug, serta hasil uji ulang.
Build test setelah implementasi modul
gcc -std=c17 -Wall -Wextra -Wpedantic -Iinclude tests/test_checkout.c src/input.c src/storage.c src/checkout.c -o build/test_checkout.exe
.\build\test_checkout.exe

03Audit konsistensi file

  1. Cocokkan END|N dengan jumlah record yang dibaca.
  2. Pastikan ID master/nota unik dan setiap referensi menunjuk record yang ada.
  3. Pastikan setiap SALE memiliki minimal satu ITEM; pasangan sale_id/product_id unik.
  4. Hitung ulang total detail dengan pemeriksaan overflow; cocokkan SALE.total dan paid ≥ total.
  5. Pastikan stok ≥ 0 dan quantity > 0.
  6. Bandingkan salinan file utama sebelum/sesudah uji gagal; pastikan tidak ada penjualan parsial.
Penanda END mendeteksi beberapa bentuk pemotongan, bukan checksum atau perlindungan terhadap semua perubahan file. Skenario kerusakan dan pemulihan tetap wajib diuji.
