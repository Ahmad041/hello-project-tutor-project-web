Kapan dikerjakan? Siapkan kasus uji dan kerangka dokumen sekarang. Setelah latihan program tersedia, kembali ke modul ini untuk menjalankan uji, mengisi hasil aktual, dan mengambil screenshot. Nomor modul mengelompokkan materi; hasil testing mengikuti waktu pelaksanaan.

Identifikasi penguji dan lingkungan, siapkan data awal, tuliskan langkah serta ekspektasi, lalu jalankan program. Isi hasil test, tester, tanggal, bukti, dan keterangan sesuai kejadian. Jika gagal, tulis defect dan uji ulang setelah perbaikan.

Template menyebut API dan DBMS. Untuk latihan C/TXT tanpa API/DBMS, tulis Tidak digunakan dan jelaskan fungsi C serta format file. Contoh klaim performa atau keamanan pada template bukan hasil atau kewajiban yang otomatis berlaku bagi KasirKita.

Contoh isi teknis: fungsi PrintTxt membaca assets/ascii/judul.txt relatif terhadap direktori kerja; salinan fungsi memeriksa hasil fopen sebelum fgets. Sertakan versi source, rancangan layar, dan hasil uji file hilang setelah percobaan dilakukan.

Gunakan bahasa pengguna, bukan jargon implementasi. Screenshot dan langkah harus mengikuti program versi yang didokumentasikan.

Contoh petunjuk pengguna untuk kejadian yang sama: buka PowerShell di folder kasirkita, jalankan .\build\latihan.exe. Jika judul tidak tampil dan muncul pesan file tidak dapat dibuka, periksa assets/ascii/judul.txt serta folder tempat program dijalankan. Pengguna tidak perlu membaca implementasi PrintTxt.

Hasil modul 2: proposal, Product Documentation, dan User Guide yang merujuk versi yang sama, beserta catatan testing. Pada tahap persiapan, kerangka dan kasus uji cukup; setelah program dicoba, lengkapi hasil aktual, bukti, defect, serta hasil uji ulang tanpa mengarang status lulus.
