02Proses bisnis penjualan

BAHAN DOWNLOAD

Dokumen Probis

Flowchart, ERD, PDM, DFD, dan daftar fitur.

Unduh Dokumen Probis ↓

Kasir memilih produk, memasukkan jumlah, dan menerima uang tunai. Program memvalidasi input, menyiapkan perubahan di memori, lalu menyimpan satu snapshot data lengkap.

Jika stok/uang tidak cukup → kembali ke input. Jika penulisan gagal → jangan nyatakan penjualan berhasil; pertahankan versi data sebelumnya. Jika file utama tidak dapat dipulihkan, hentikan transaksi dan gunakan prosedur pemulihan.

03ERD awal · sebelum normalisasi

Mulai dari bentuk nota kertas. Relasi konseptualnya: satu pelanggan dapat memiliki banyak nota; setiap nota berisi banyak produk. Penyimpanan awal berikut belum normal karena item disimpan sebagai daftar berulang.

Masalah: nama pelanggan dan kategori berulang; mengganti nama memerlukan banyak pembaruan. Array item menyulitkan query jumlah barang terjual. Ini model awal untuk dianalisis, bukan skema yang dipakai aplikasi.

04PDM · normalisasi hingga 3NF

ERD dan normalisasi tetap digunakan untuk merancang hubungan data meskipun program tidak memakai database SQL. Model fisik di bawah memetakan entitas ke jenis record dalam file teks.

Tahap Perubahan Tujuan
1NF Pisahkan daftar item nota menjadi record ITEM Satu nilai per field
2NF Pisahkan header SALE dan master PRODUCT Atribut bergantung pada kunci record
3NF Pisahkan CATEGORY dan CUSTOMER Nama kategori/pelanggan tidak diulang pada master/transaksi lain
PK = identitas unik; REF = referensi antar-record. File TXT tidak menegakkan constraint otomatis. Program C harus memeriksa keunikan ID, referensi, dan rentang angka saat membaca maupun menyimpan.

05Denormalisasi yang terkontrol

Tambahkan total pada record SALE untuk menyimpan hasil penjumlahan quantity × unit_price. Nilainya diperiksa ulang saat file dibaca. Kembalian dihitung dari paid − total dan tidak disimpan.

unit_price menyimpan harga saat transaksi, sehingga nota lama tidak berubah saat harga master diedit. Seluruh record disimpan dalam satu data.txt untuk menghindari ketidaksesuaian akibat memperbarui beberapa file secara terpisah.

Level 1 — proses dan penyimpanan

Proses Aliran data Penyimpanan logis
1.0 Kelola master Pemilik → kategori/produk/pelanggan → validasi → konfirmasi D1: record CATEGORY, PRODUCT, CUSTOMER
2.0 Penjualan Kasir → keranjang & bayar; baca D1 → nota; ubah stok D1 dan D2: SALE, ITEM
3.0 Laporan Pemilik → tanggal; baca D2 → jumlah nota & omzet D2: hanya baca
D1 dan D2 berada dalam file fisik data/data.txt yang sama. File nota dalam output/ adalah hasil ekspor; bukan sumber data utama.
